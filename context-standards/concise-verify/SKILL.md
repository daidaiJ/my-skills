# /concise-verify — 精要输出 + 验证兜底

## 核心原理

验证器模式让"精简"成为可能：**生成阶段不预先自我怀疑**，直接给最精要版本；
正确性由验证环节兜底。验证不是二元对错，而是**细粒度连续打分**——多标准、
逐条评分、低分定位到具体缺陷。这样 agent 敢于压缩输出，因为错误会被抓住并修复。

## 触发场景

- 用户要求"最精要 / 最短 / 一句话 / 别啰嗦"，但结果必须正确
- "快速给方案但质量要高"、"少说废话但别出错"
- 输出长度受限（终端、消息、摘要），但正确性关键（代码、数字、事实性结论）

## 流程

### 阶段 0：定义细粒度标准（3-5 条）

先明确"达标"长什么样。标准要具体可判，按任务裁剪：

| 标准 | 判据 |
|------|------|
| 正确性 | 事实 / 代码 / 数字 / 结论无错 |
| 完整性 | 覆盖用户问题的所有要点，无遗漏 |
| 精要度 | 无冗余，每句都有信息量 |
| 可执行性 | 方案可直接照做（如适用） |
| 针对性 | 直接回答，不绕弯、不加免责声明 |

### 阶段 1：精简生成

直接产出最精要版本。不写草稿再压缩，不预先自我怀疑。

- 每句必须有信息量；删过渡句、自我解释、免责声明
- 结论先行，细节按需展开
- 代码 / 命令 / 数字 / 专有名词原样保留，不缩写

### 阶段 2：细粒度验证（连续打分，非二元）

逐条标准打分 1-5：

- **5** 达标；**4** 基本达标；**≤3** 必须修复
- 低分项必须定位到**具体缺陷**（哪句、哪个事实、缺哪个要点），不许笼统说"不够好"
- 打分要快：单候选默认 1 轮，不反复自我怀疑

### 阶段 3：修复或重选

- **单候选（默认）**：按缺陷清单修复 → 回到阶段 2。最多 2 轮。
- **多候选（仅正确性风险高时）**：生成 2-3 个精简候选 → **枢轴锦标赛**选优：
  1. 自评各候选，最高分者为枢轴
  2. 其余候选只与枢轴对比（不做全两两比较）
  3. 胜者若仍有 ≤3 分项，修复后输出
- 2 轮后仍有 ≤3 分项：输出当前最佳 + 一句话说明已知局限，**不无限循环**

### 阶段 4：多步任务进度跟踪（可选）

任务分多步时，每完成一步先验证再继续：

- 步骤得分 **< 3** → 立即停，换路径或重做该步，不硬撑
- 步骤得分 **≥ 4** → 继续，不回头检查

## 成本控制

- 默认预算：1 次生成 + 1-2 轮验证
- 多候选仅当：正确性风险高（代码、数字、事实性结论）且用户明确要"最优"
- 验证轮次上限 2；超限输出最佳可得 + 局限说明

## 与相关 skill 的边界

| Skill | 定位 | 区别 |
|-------|------|------|
| `caveman` | 纯压缩通信 | 无验证兜底；正确性关键时用 concise-verify |
| `self-verify` | 事后全量审计 | PASS/FAIL 二元裁决、子代理；concise-verify 是生成时内联验证，更轻 |
| `verify-chain` | 外部事实核查 | 联网搜索验证；concise-verify 基于任务上下文自检，不联网 |

## 示例

**示例 1：一句话定义**

用户："用一句话解释什么是数据库索引，但要准确"

- 阶段 1 生成："索引是数据库为加速查询而维护的额外数据结构，以空间换时间。"
- 阶段 2 验证：正确性 5（定义准确）；完整性 4（未提 B+ 树等实现，一句话场景可接受）；精要度 5
- 直接输出，无需修复。

**示例 2：最简可运行代码**

用户："给个最简的 Python 脚本读取 CSV 并打印每行长度，要能直接跑"

- 阶段 1 生成：`import csv; [print(len(r)) for r in csv.reader(open('f.csv'))]`
- 阶段 2 验证：正确性 3——`open` 未关闭、列表推导带副作用、无编码处理
- 阶段 3 修复：`import csv; f=open('f.csv'); [print(len(r)) for r in csv.reader(f)]; f.close()`
- 再验证：正确性 4（仍可再简化为 with 语句，但已可直接运行）；输出。
