# 与 i-have-adhd、caveman 的叠加

本 skill 只管句式层。另两层由已装的 skill 提供。三个 skill 可以同时开。

## 三层分工

| 层 | 管什么 | 来源 |
| --- | --- | --- |
| 结构层 | 首行给下一步行动、多步工作编号、跨轮重述状态、列表不超过 5 项、无铺垫无收尾 | `i-have-adhd` |
| 句式层 | 句长上限、一句一事、祈使句、主动句、条件在前、一词一义 | 本 skill |
| 压缩层 | 删虚词与铺垫、片段化、箭头表因果 | `caveman` |

句式层一直生效。另两层按需叠加：用户开了 caveman 就叠压缩层；读者需要行动导向，或用户要求 ADHD 友好输出，就叠结构层。

## 冲突裁决顺序

按顺序取先满足的那条，低编号赢：

1. 安全与不可逆操作：确认，写清后果，可以临时展开写。
2. 事实与模态保真：数字、条件、可能性、确定程度。
3. 歧义消除：本 skill 的句式与词表规则。
4. 可扫读结构：`i-have-adhd` 的排版与编号。
5. 压缩：`caveman`。

压缩永远输给前四条。caveman 自己有例外条款（不可逆操作要展开），i-have-adhd 也要求破坏性操作先确认，三者在第 1 条上一致。

## 不可压缩清单

caveman 的规则为英文而写：删冠词、删虚词、允许片段。中文里这样删会撞到别的东西。以下成分删掉会改意思或改事实，压缩时保留：

- 否定与限定：不、未、无、非、仅、只、除非、除了
- 执行者：谁做这件事（系统 / 你 / 采集器 / 脚本）
- 数量、单位、比较符：不小于、最多、3 次、2 秒、5 GB
- 条件与前置条件：如果、当、除非、在……之前
- 模态强度：必须 / 建议 / 可以 / 可能
- 时点与时长：2026-12-31、30 分钟
- 原文引用：报错信息、代码、命令、路径、字段名、版本号、URL
- 警告的后果与不可逆性

可以删的：礼貌语（请、您、感谢）、铺垫（我们来看、接下来、值得注意的是）、已由编号表达顺序的连接词（首先、然后、最后）、同义重复、无信息的程度词（很、非常、比较）、解释性从句。

## 判断压缩有没有压坏

把压缩后的句子读一遍，问四个问题：谁做、做不做、什么条件下做、做了会怎样。有一个答不上来，就补回去。

三组压坏的反例与修复见 [examples.md](./examples.md) 第五组。
