# 简明技术中文（STE-zh）

目标：读者读一遍就不会读错。做法：限制用词，限制句式，一句一事。

细则在 references/：完整规则 [rules.md](./references/rules.md)，受控词表 [vocab.md](./references/vocab.md)，四模式对照 [examples.md](./references/examples.md)，来源与映射 [sources.md](./references/sources.md)。

## 三层分工

这个 skill 只管一层。另外两层由已装的 skill 提供。

| 层 | 管什么 | 来源 |
| --- | --- | --- |
| 结构层 | 首行给下一步行动、多步工作编号、跨轮重述状态、列表不超过 5 项、无铺垫无收尾 | `i-have-adhd` |
| 句式层 | 句长上限、一句一事、祈使句、主动句、条件在前、一词一义 | 本 skill |
| 压缩层 | 删虚词与铺垫、片段化、箭头表因果 | `caveman` |

句式层是用中文写技术内容时的默认层，一直生效。另外两层按需叠加：用户开了 caveman 就叠压缩层；读者需要行动导向，或用户要求 ADHD 友好输出，就叠结构层。三层可以同时开。

## 冲突裁决

按顺序取先满足的那条，低编号赢：

1. 安全与不可逆操作（确认、写清后果，可临时展开）
2. 事实与模态保真（数字、条件、可能性、确定程度）
3. 歧义消除（本 skill 的句式与词表规则）
4. 可扫读结构（i-have-adhd）
5. 压缩（caveman）

压缩永远输给前四条。

## 不可压缩清单

caveman 的规则为英文而写：删冠词、删虚词、允许片段。中文里这样删会撞到别的东西。压缩时保留这些成分，删掉会改意思或改事实：

- 否定与限定：不、未、无、非、仅、只、除非、除了
- 执行者：谁做这件事（系统 / 你 / 采集器 / 脚本）
- 数量、单位、比较符：不小于、最多、3 次、2 秒、5 GB
- 条件与前置条件：如果、当、除非、在……之前
- 模态强度：必须 / 建议 / 可以 / 可能
- 时点与时长：2026-12-31、30 分钟
- 原文引用：报错信息、代码、命令、路径、字段名、版本号、URL
- 警告的后果与不可逆性

可删的：礼貌语（请、您、感谢）、铺垫（我们来看、接下来、值得注意的是）、已由编号表达顺序的连接词（首先、然后、最后）、同义重复、无信息的程度词（很、非常、比较）、解释性从句。

## 必须级规则速览

句：

- 操作句不超过 30 字，描述句不超过 40 字。超了拆句。
- 一句一个主干动作。分号不能把两句并成一句。
- 操作句用祈使句，动词开头。不写「请」「您」「用户需要」「应该」。
- 用主动句，写出执行者。「被」「由」「受到」是被动信号。
- 条件写在动作前面。不放句尾，不放括号。
- 一句最多一个否定。不用「不得不」「没有……不」。
- 「其」「该」「此」「它」只指代上一句里的对象。否则重复名词。

词：

- 一个概念全文只用一个词。不为避免重复换同义词。
- 不用「进行」「加以」「作出」「予以」加动词。直接用动词。
- 不用没有数值的程度词与估计词：很、非常、比较、大量、尽快、及时、大概、若干。
- 不用黑话：赋能、抓手、闭环、拉通、沉淀、痛点、打法、颗粒度。
- 缩写首次出现写全称并括注，之后固定写法。

段与步骤：

- 一段一个主题，不超过 6 句。
- 步骤用编号列表，每个编号一个动作。不在正文里写「首先……然后……」。
- 不用「等」结尾的开放列举。列全，或写数量加「包括」。
- 警告独立成段，放在它针对的步骤之前，以「警告：」或「注意：」开头。
- 人的动作用祈使句，系统的行为写「系统 + 动词」。

数字与标记：

- 用阿拉伯数字，数字与单位之间空一格。
- 不用数字后的「以上」「以下」「以内」。写「大于」「不小于」「不超过」，或「3 至 5（含）」。
- 减少不用「倍」。百分比和百分点分开写。
- 界面元素名用「」括起，与界面文字一致。代码、命令、路径、字段名用行内代码原样保留。

## 中文特有的歧义

这些是英文规则覆盖不到的地方，中文写作的主要失分点：

| 歧义 | 改法 |
| --- | --- |
| 「10 以上」含不含 10，读者不统一 | 写「大于 10」或「不小于 10」 |
| 「可以」既表许可又表能力 | 许可用「可以」，能力用「支持」 |
| 「对配置进行修改」名词化 | 直接用动词：「修改配置」 |
| 名词前修饰语太长 | 超过 15 字拆句。连续多个「的」是信号 |
| 中文习惯省略主语 | 操作句省（读者是默认执行者），描述句写出来 |
| 无标记被动：「配置已更新」 | 看不出谁更新的，写「系统更新了配置」 |
| 「支持 A、B 等」开放列举 | 列全，或「包括 3 种：A、B、C」 |
| 「A 和 B、C」分组不明 | 同级用顿号，末项用「和」；两层以上改列表 |
| 相对时间：「近期」「尽快」 | 写绝对日期或时长 |
| 「打开」对象不限 | 文件、窗口、页面、连接用「打开」；功能用「启用」；程序用「启动」 |

词表里的完整对照见 [vocab.md](./references/vocab.md)。

## 组合后的样子

同一件事，五种写法。内容来自 [examples.md](./references/examples.md) 的第一组。

**默认（无 skill）**

> 关于超时时间这个配置项，目前可能存在一些不太合理的地方。在文件体积比较大的情况下，上传请求有可能会因为超时而被中断，建议可以考虑适当调大该值。

**只开句式层（本 skill）**

> 上传大文件时，请求会超时中断。把超时时间从 10 秒改为 60 秒。

**句式层 + i-have-adhd**

> 把超时时间从 10 秒改为 60 秒。
>
> 1. 打开 `config.yaml`
> 2. 把 `timeout` 改为 `60`
> 3. 重启服务
>
> 原因：默认 10 秒，大文件上传会中断。

**句式层 + caveman**

> 超时 10 秒 → 大文件上传中断。改 60 秒：`config.yaml` 的 `timeout`。

**三层全开**

> 改超时时间：`config.yaml` 的 `timeout` 改成 60。
>
> 1. 改 `timeout: 60`
> 2. 重启服务
>
> 10 秒 → 大文件上传断。

## 发送前自检

1. 操作句超过 30 字了吗？里面有两个动作吗？缺执行者吗？
2. 否定词、数字、单位、条件、模态词有没有被压缩掉？
3. 同一个概念在全文换过词吗？
4. 条件、警告、前置条件都放在动作前面了吗？
5. 描述句的主语在不在？
6. 还有「进行」「等」「以上」「尽快」「大概」「相关」吗？

## 不要做的事

- 不改写代码、命令、路径、字段名、URL、报错原文。
- 不为了短而删条件、例外、警告、数字。
- 不把「可能」改成「会」，不把「建议」改成「必须」。
- 不给原文没有的数字、日期、时限编一个。缺信息写「待确认」。
- 不用在营销文案、叙事文章、法律原文、引用原文上。
- 改写别人的文稿时，事实、数字、条件和确定程度保持不变。
