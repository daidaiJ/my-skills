# Handoff — 跨会话任务交接

## 目标

让下个会话进入工作空间就能接续之前会话交接的任务；任务完成后自动从 `AGENTS.md` 中摘除关联摘要块，不留死链接。

## 双场景路由（渐进式披露：按场景加载，勿整篇吞）

| 场景 | 触发 | 读什么 |
|------|------|--------|
| **写交接**（保存进度 / 收口回填 / 完成清理 / git 同步开关） | 用户说"handoff"、"交接"、"先存一下进度"，或批次收口要回填 | [references/writing.md](references/writing.md)——存储结构、12 节模板、AGENTS.md 摘要块标准、膨胀与腐化防线、写入流程与自检、完成清理 |
| **恢复交接**（接续之前的任务） | 用户说"继续"、"完成之前"、"遗留"、"剩下的"、"交接的任务" | [references/recovery.md](references/recovery.md)——轻路径：**通常 AGENTS.md 摘要就已够用**，下钻是例外 |

## 核心原则（两场景共用）

| 原则 | 说明 |
|------|------|
| **项目隔离** | handoff 只属于单个项目，始终存放在项目根目录下的 `.handoff/` 子目录，禁止写入任何全局路径或仓库外路径 |
| **双层结构** | 详情层（完整 handoff 文档）＋ 入口摘要层（AGENTS.md 里的精简引用块），两层互相引用 |
| **入口不膨胀** | AGENTS.md 摘要块是**当前状态快照，不是增量日志**：单块 ≤ 10 行、整块原地覆盖写、禁止历史叙事。已观察到的反面案例：某项目 AGENTS.md 因每轮新增批次卡膨胀到 500+ 行，用户被迫下令砍回摘要 |
| **不重复存储** | handoff 通过引用复用 wiki/专题文档资产，外部文档已有的内容不重复抄录，只放指针；证据/详情段整段复述外部文档 = 腐化，当场砍（渐进式披露：卡 = 状态 + 指针 + 开口项） |
| **隐私不记录** | 用户的密钥、token、私密配置等隐私数据不写入 handoff |
| **冷热分离** | 活跃任务的 handoff 是热层，接手会话只读 AGENTS.md 摘要块 + 对应详情文件；已完成/废弃任务**及时**移入 `.handoff/archive/`（冷层，只追加、不改写）——归档不等任务收口：热文件里已完成的小节、已验证的检查项、失效开口项随每次更新就地删剪或移出，冷信息不滞留热层 |
| **首读链瘦身** | agent 最先读到的几层（AGENTS.md 摘要块 → 热层 handoff → 指针命中的第一份专题文档）是上下文链路的入口：热层 handoff 的**首读事实块 ≤ 10 行**（当前任务 / 现场 / 开口项 / 指针各一两句），每层只放「状态 + 指针 + 开口项」，细节一律下沉到链路末端的专题文档/archive；任何一层出现历史叙事、整段复述、滞留的已完成内容，当轮修剪 |
| **git 同步开关** | `.handoff/` 默认不入 git（交接噪音与隐私不进仓库历史）；用户明确要求 git 同步交接时摘除 ignore（writing.md「git 同步开关」节），使交接记录随仓库跨设备同步 |
| **交接链自足** | 凭 handoff 串联的上下文（入口摘要块 + 交接卡 + 卡内指针）就能定位全部详情文档并交付接力任务，**脱离会话记忆**；卡核心两块 = ①上一批完成记录（可核查：commit + 测试证据 + 权威规格）②下一批任务单（做什么 / 计划在哪 / 怎么验收 / 约束），其余一律摘要 + 指针 |
| **最新即真理** | handoff 内容每次写入时覆盖旧值，保证信息始终是最新的；摘要块与详情层出现矛盾时以详情层为准，并立即重写摘要块消除矛盾（腐化零容忍） |
| **完成后清理** | 任务完成后从 `AGENTS.md` 摘除摘要块，详情文档移入 `.handoff/archive/`，并告知用户 |

## 双层结构速览

```
AGENTS.md 摘要块（≤10 行/块，入口层——恢复场景通常读到这里就够）
  └─ .handoff/<任务名>.md（热层详情，覆盖写；完成 → archive/ 冷层）
       └─ 卡内指针 → 专题文档（规格分册 / 取证附录 / pitfalls）
```

两份场景手册：写交接 → [references/writing.md](references/writing.md)；恢复交接 → [references/recovery.md](references/recovery.md)。
