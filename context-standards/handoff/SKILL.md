# Handoff — 跨会话任务交接

## 目标

让下个会话进入工作空间就能接续之前会话交接的任务；任务完成后自动从 `AGENTS.md` 中摘除关联摘要块，不留死链接。

---

## 核心原则

| 原则 | 说明 |
|------|------|
| **项目隔离** | handoff 只属于单个项目，始终存放在项目根目录下的 `.handoff/` 子目录，禁止写入任何全局路径或仓库外路径 |
| **双层结构** | 详情层（完整 handoff 文档）＋ 入口摘要层（AGENTS.md 里的精简引用块），两层互相引用 |
| **不重复存储** | handoff 通过引用复用 wiki 资产，wiki 里已有的内容不重复抄录，只放指针 |
| **隐私不记录** | 用户的密钥、token、私密配置等隐私数据不写入 handoff |
| **最新即真理** | handoff 内容每次写入时覆盖旧值，保证信息始终是最新的 |
| **完成后清理** | 任务完成后从 `AGENTS.md` 摘除摘要块，并告知用户 |

---

## 存储结构

```
项目根目录/
├── .handoff/                          # 项目专属，不加入 git
│   └── <任务名>.md                     # 单个任务 handoff 文档
│
└── AGENTS.md                          # Agent 入口文件
```

### 文件名约定

```
<任务名短横线化>.md
```

- 同一任务进度更新时复用同一文件（覆盖写入），保持文件名不变。
- 多个活跃任务各占一个文件。

## 第一层：详情层 — `.handoff/<任务名>.md`（完整文档标准）

### 模板骨架

```markdown
---
handoff_id: <任务名>
status: active | completed | blocked
---

## 1. 目标

一句话说明这个任务要达成什么。

## 2. 当前进度与状态

- **当前阶段：** <描述>
- **状态：** in-progress / blocked / done
- **进度百分比（可选）：** <数字>%

## 3. 关键证据

- <用一句话或一句话列表描述当前最重要的发现或数据>
- 如果有日志、截图、API 响应等，放在代码块里

## 4. 排查方向（仅 debug 任务）

<当前怀疑方向、已排除方向、下一步验证步骤>

## 5. 验收标准

- [ ] <可验证的标准 1>
- [ ] <可验证的标准 2>

## 6. 后续待完成的任务和步骤

1. <步骤 1，按执行顺序列出>
2. <步骤 2>
3. …

## 7. 资产与使用说明

| 资产 | 路径 / 引用 | 用途 |
|------|------------|------|
| 脚本 | `scripts/xxx.sh` | <说明> |
| 配置 | `.env.example` | <说明> |
| Wiki | `wiki/xxx.md` | <说明> |

> ⚠️ wiki 资产只写引用路径，不抄录内容。

## 8. 注意事项

- **已踩过的坑：** <之前流程中犯的错和应对方法>
- **用户认同的稳定执行流程：** <用户口头确认过的有效做法，原文记录>
- **环境限制：** <约束、依赖、版本要求>

## 9. 用户偏好

- <用户口头澄清的内容，强调并原文记录>

## 10. 建议使用的 Skill 和 MCP

- **Skill：** <建议 skill 名及简短理由>
- **MCP：** <建议 MCP 服务器及简短使用建议>
- **运行时建议：** <简短执行建议，如顺序、并行方式>

## 11. 用户下个会话聚焦重点

- <本次会话用户 arguments 中明确提到的后续重点，用于裁剪下次会话的上下文>

## 12. 明确标注为验证的事项（未完成勿删）

> ⚠️ 以下事项**尚未完成验证**，下个会话不得默认其为已完成。

### 已执行、待验证

- [ ] <验证项 1> — <一句话说明当前状态，如"代码已提交 PR #42，待 reviewer 通过">
- [ ] <验证项 2> — <一句话说明>

### 已完成且已验证

- [x] <已验证项 1> — <一句话确认，如"单元测试全部 PASS（3/3），见 CI #123">
- [x] <已验证项 2>
```

### 各节填写规则

| 节 | 必填 | 说明 |
|----|------|------|
| 1. 目标 | ✅ | 一句话 |
| 2. 当前进度 | ✅ | 阶段 + 状态 + 可选百分比 |
| 3. 关键证据 | ✅ | 一两句话或数据块 |
| 4. 排查方向 | 仅 debug | 怀疑方向 + 已排除 + 下一步验证 |
| 5. 验收标准 | ✅ | 可逐条打勾 |
| 6. 后续步骤 | ✅ | 按执行顺序列出 |
| 7. 资产 | ✅ | 只写引用，不抄录 |
| 8. 注意事项 | ✅ | 坑点 + 稳定流程 + 环境限制 |
| 9. 用户偏好 | ✅ | 口头澄清原文记录 |
| 10. Skill / MCP | 可选 | 建议及简短理由 |
| 11. 下个会话聚焦 | 可选 | 裁剪后续上下文 |
| 12. 验证事项 | ✅ | 双列：待验证 vs 已验证，不得省略 |

## 附录 A：进度格式（三种可选方案）

Agent 在填写 **"当前进度与状态"** 和 **"后续待完成的任务和步骤"** 时，
根据任务性质从以下三种格式中任选一种或组合使用，不强制统一。

### 格式 A — Todo 列表（适用于有明确执行步骤的任务）

```markdown
## 2. 当前进度与状态

- **当前阶段：** Step 3 / 5
- **状态：** in-progress
- **进度百分比：** 60%

### 已完成
- [x] Step 1 — 搭建项目脚手架
- [x] Step 2 — 实现 API 路由
- [ ] Step 3 — 集成数据库（**当前**）
- [ ] Step 4 — 编写单元测试
- [ ] Step 5 — 提交 PR

### 阻塞项
- [ ] Step 3 需要等待 DBA 提供连接字符串
```

### 格式 B — 列表（适用于状态类、检查类任务）

```markdown
## 2. 当前进度与状态

- **状态：** in-progress

### 检查清单
- ✅ K8s 集群可访问
- ✅ Ingress 配置已推送
- ✅ 证书已签发
- ❌ Pod 健康检查未通过（见排查方向）
- ⏳ 等待日志分析结果
```

### 格式 C — 量化描述（适用于测试、批处理、对比类任务）

```markdown
## 2. 当前进度与状态

- **状态：** in-progress
- **测试结果：** 3/5 PASS · 2 FAIL
- **批次进度：** Batch 2 / 4

### 用例详情
| #  | 用例名       | 结果  | 备注                  |
|----|-------------|-------|-----------------------|
| 1  | login_flow  | PASS  |                       |
| 2  | signup_flow | PASS  |                       |
| 3  | reset_pwd   | PASS  |                       |
| 4  | oauth_sync  | FAIL  | 超时，待重跑          |
| 5  | rate_limit  | FAIL  | 阈值配置错误，已修复  |
```

**选择指南：**

| 场景 | 推荐格式 | 理由 |
|------|----------|------|
| 多步骤实施任务 | A — Todo 列表 | 步骤可勾选，进度一目了然 |
| 状态检查 / 配置核对 | B — 列表 | 轻量，适合快速扫读 |
| 测试 / 批处理 / 对比 | C — 量化描述 | 数字和表格最能反映覆盖率 |
| 混合场景 | A + B 或 A + C 组合 | 先列 Todo，再附量化快照 |

两种格式可以出现在同一个 handoff 文件的不同节，也可以分别在详情层和 AGENTS.md 摘要层使用不同格式。

## 第二层：`AGENTS.md` 摘要块标准

在每个需要关联 handoff 的项目 `AGENTS.md` 中嵌入以下格式的摘要块。**每个活跃任务对应一个块**，任务完成后删除对应块。

```markdown
## 🔄 Handoff 摘要

### <任务名> — <状态>

- **当前状态：** <in-progress / blocked / done>
- **关键证据：** <一句话关键证据>
- **验收标准：** <一句话说明已完成的验收标准，或写"见 handoff 详情" >
- **详情指针：** [`.handoff/<任务名>.md`](.handoff/<任务名>.md)
- **遗留清理命令（可选）：**
  ```bash
  <清理残留的命令，如删除临时文件、停止后台进程>
  ```

### 未验证事项

- [ ] <验证项 1>
- [ ] <验证项 2>
```

**格式要求：**
- 最少有一句内容关联 handoff。
- 包含当前状态、关键证据一句话、验收标准。
- 通过相对路径引用 handoff 详情文件，不抄录全文。
- 明确标注为验证的事项要列出来，让下个会话知道哪些还没做完。

## 附录 B：验证核验清单

> 以下检查点覆盖 handoff 执行全流程：写入前 → 写入后 → 接续时 → 清理时。
> 复杂场景按需逐条核对。

### 写入前

- [ ] 确认 `.handoff/` 目录在**项目根目录**下，不在其他位置。
- [ ] 确认目录尚未加入 git（`.gitignore` 中应有 `.handoff/` 条目）。
- [ ] 如有敏感信息，已在写入前移除或脱敏。

### 写入后

- [ ] `AGENTS.md` 中的摘要块格式正确（有状态、关键证据、详情指针）。
- [ ] `.handoff/` 内的 handoff 文档包含全部 12 个必填节。
- [ ] handoff 文档的 `status` 字段与实际情况一致（`active` / `completed` / `blocked`）。
- [ ] wiki 资产节只写引用路径，无内容抄录。

### 恢复 / 接续时

- [ ] 按主题和关键词匹配到了正确的 handoff 文件，未读错文件。
- [ ] 已向用户或 Agent 明确展示当前活跃任务和下一步步骤。
- [ ] 已确认未验证事项清单中的 `[ ]` 项尚未完成，不会误判为已完成。

### 清理时（任务完成后）

- [ ] `AGENTS.md` 中对应任务的摘要块已完全删除，无残留注释或空块。
- [ ] handoff 文档的 `status` 已更新为 `completed`（归档用，可保留历史记录）。
- [ ] 已告知用户：`"✅ 任务 <任务名> 已完成，AGENTS.md 中的摘要引用块已清除。"`

### 未验证事项定义与填写规则

**为什么要单独列举：** 任务可能"已完成执行"但"尚未验证"，两者绝不能混淆。
下个会话必须一眼看出哪些项只是做完了，哪些项已经确认过。

**定义：**
- **已完成** = Agent 已执行该步骤，产出结果。
- **已验证** = Agent 已执行该步骤，且已通过验收标准确认产出符合预期。
- **未验证** = Agent 已完成执行，但尚未确认是否符合预期，**不等于未开始**。

**填写规则：**
1. **只要未验证就写 `[ ]`**，不管代码/配置/文档是否已写完、已提交。
2. **已通过验收标准的写 `[x]`**，并附一句话确认依据（如 CI 编号、截图路径）。
3. **同一个验证项不能同时在"待验证"和"已验证"两列中出现**，避免歧义。
4. **验证完成后立即从"待验证"移到"已验证"并打勾**，再更新 `status: completed` 并清理 AGENTS.md 摘要块。
5. **不以"我以为"或"大概"作为验证依据**——有明确结论（PASS / PASSED / 截图 / 日志行号）才算已验证。

## Agent 执行流程

### 写入 handoff（保存进度）

1. **读取 `AGENTS.md`**：确认是否已有该任务的摘要块。
2. **确认 `.handoff/` 目录存在**：不存在则创建。
3. **写入完整 handoff 文档**：按上方模板填充，覆盖旧文件，内容必须是当前最新状态，不复制历史旧的错误信息。
4. **写入或更新 `AGENTS.md` 摘要块**：按上方格式插入或更新。
5. **告知用户**：确认文件已写入，并告知 handoff 位置。

### 恢复 / 继续任务

当用户说"恢复"、"继续"、"完成之前"、"遗留"、"剩下的"、"交接的任务"等意图时：

1. **读取 `AGENTS.md`**：找到所有 handoff 摘要块，识别活跃任务。
2. **按主题和相关性检索 `.handoff/`**：根据用户意图和摘要块关键词，定位最相关的 handoff 文档。
3. **重建上下文**：全文读取匹配的 handoff 文档，呈现给用户或直接用于继续执行。
4. **继续执行**：按 handoff 中的步骤顺序继续工作。

### 完成清理（自动摘除）

当 Agent 确认任务已全部完成并通过验收标准时：

1. **从 `AGENTS.md` 中删除该任务的摘要块**。
2. **将 handoff 文档的 `status` 字段改为 `completed`**（可选归档，不删除）。
3. **告知用户**：`"✅ 任务 <任务名> 已完成，AGENTS.md 中的摘要引用块已清除。"`
