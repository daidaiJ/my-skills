# 恢复交接（场景二：接续之前的任务）

> 由 SKILL.md「双场景路由」进入。本场景走轻路径：**通常 AGENTS.md 摘要就已
> 够用**，下钻是例外——每层只付按需的成本。

当用户说"恢复"、"继续"、"完成之前"、"遗留"、"剩下的"、"交接的任务"等意图时：

1. **先核对现场**：`git log` + `git status` + 工作区 diff，**禁止凭记忆续写**——先确认仓库实际状态。
2. **读 `AGENTS.md` 摘要块**：状态 / 关键证据 / 验收 / 详情指针各一行——**通常到此即可接续**；摘要块回答的就是「此刻停在哪、下一步是什么」。
3. **下钻是例外**：仅当摘要不够用（需要计划细节、验收清单、核查上一批完成记录）才沿指针走：
   - 热层交接卡的**首读事实块**（≤ 10 行：当前任务 / 现场 / 开口项 / 指针）；
   - 卡内两块核心——上一批完成记录（可核查：commit + 测试证据 + 权威规格）与交接任务单（做什么 / 计划在哪 / 怎么验收 / 约束）；
   - 卡内指针命中的专题文档（规格分册 / 取证附录 / pitfalls）；
   - 更早脉络与取证锚点查 `.handoff/archive/`。
4. **交付接力**：凭上述上下文继续执行；定位链靠仓库自身的文件（AGENTS.md → 交接卡 → 专题文档），**不依赖会话记忆**。
5. **回写**：任务有进展或完成 → 回到写交接场景（[writing.md](writing.md)）更新摘要块与详情层、必要时摘块归档。
