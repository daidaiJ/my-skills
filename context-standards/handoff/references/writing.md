# 写交接（场景一：保存进度 / 收口回填 / 完成清理）

> 由 SKILL.md「双场景路由」进入。本文件是写作场景全套：存储结构 → git 同步
> 开关 → 12 节模板 → AGENTS.md 摘要块标准 → 膨胀与腐化防线 → 写入流程与自检
> → 完成清理。恢复场景（场景二）不需要读本文件——通常 AGENTS.md 摘要就已够用。

## 存储结构

```
项目根目录/
├── .handoff/                          # 项目专属，不加入 git
│   ├── <任务名>.md                     # 活跃任务 handoff（热层，覆盖写）
│   └── archive/                       # 已完成/废弃任务归档（冷层，只追加、不改写）
│       └── <任务名>.md                 # 移入时文件名不变，内容 verbatim
│
└── AGENTS.md                          # Agent 入口文件
```

> `.handoff/` 默认写入 `.gitignore`（隐私与噪音隔离）；用户要求 git 同步交接时
> 摘除——见「git 同步开关」节。

### 文件名约定

```
<任务名短横线化>.md
```

- 同一任务进度更新时复用同一文件（覆盖写入），保持文件名不变。
- 多个活跃任务各占一个文件。

## git 同步开关（用户明示才动）

`.handoff/` 默认不加入 git：各设备本地各自演进，交接噪音与本地现场卡不进
仓库历史。用户说「支持 git 同步交接」「跨设备同步 handoff」「handoff 要能
跟着仓库走」或等义表述时：

1. **隐私前置检查**：快速扫一遍待入库的交接文件，确认无密钥/token/私密配置
   （既有原则）；有则先清出再摘 ignore。
2. **摘除 ignore**：从 `.gitignore` 删除 `.handoff/` 整行。**注意**：父目录被
   整体排除后，目录内文件的 `!` 反选一律不生效（`!.handoff/handoff.md` 是
   静默 no-op，无任何警告）——只想放行单个文件时，把该行改写成 `/.handoff/*`
   + `!/.handoff/handoff.md`。两种情况都以 `git status` 能看到交接文件为准。
3. **提交入库并告知**：把现有交接文件提交进仓库，告知用户此后交接记录随仓库
   同步、多设备经 pull/push 接续。
4. **反向操作（用户要求停止同步时）**：恢复 ignore 条目，并把目录移出版本
   控制（`git rm -r --cached .handoff`），本地文件保留。

## 第二层：`AGENTS.md` 摘要块标准

在每个需要关联 handoff 的项目 `AGENTS.md` 中嵌入以下格式的摘要块。**每个活跃任务对应一个块**，任务完成后删除对应块。

```markdown
## 🔄 Handoff 摘要

### <任务名> — <状态>

- **当前状态：** <in-progress / blocked / done>
- **关键证据：** <一句话关键证据>
- **验收标准：** <一句话说明，或写"见 handoff 详情" >
- **详情指针：** [`.handoff/<任务名>.md`](.handoff/<任务名>.md)
- **遗留清理命令（可选）：**
  ```bash
  <清理残留的命令>
  ```

### 未验证事项
- [ ] <验证项 1>
- [ ] <验证项 2>
```

**格式要求：**
- 最少有一句内容关联 handoff。
- 包含当前状态、关键证据一句话、验收标准。
- 通过相对路径引用 handoff 详情文件，不抄录全文。
- 明确标注为验证的事项要列出来，让下个会话知道哪些还没做完。

## 膨胀与腐化防线（多轮更新时必守）

摘要块死掉只有两种方式——**膨胀**（越写越长）和**腐化**（信息过时、与详情层
矛盾）。多轮交接更新时逐条对照：

### 摘要块防线

**防膨胀（结构约束）：**

1. **单块 ≤ 10 行**（含空行与标题；「未验证事项」列表另计但 ≤ 5 行）。写不下
   = 内容属于详情层，压成一行指针放块里，全文进 `.handoff/<任务名>.md`。
2. **原地整块覆盖，禁止追加**：同一任务的进度更新重写同一个块，**绝不新增
   `###` 兄弟小节**——会话轮次不产生新块，"上一批""上一阶段"式的历史小节
   就是膨胀开始的标志。
3. **一任务一块**：活跃块数量 = 活跃任务数量；多任务并存时 AGENTS.md 中
   handoff 块合计 ≤ 30 行，超出就把次要任务的块压成单行指针。
4. **每行单一职责**：状态 / 证据 / 验收 / 指针各一行，不合并叙事。

**防腐化（内容约束）：**

5. **只描述"现在"**：块内禁止时间叙事链（"上一阶段…再上一阶段…第 N 批…"）
   与历史对比；详情层负责历史，块只回答"此刻停在哪、下一步是什么"。
6. **每轮更新 = 以详情层为唯一事实源重写整块**：重写后逐行自问"这句还成立
   吗？"——过时的阶段描述、已完成却未勾的验证项、指向已归档文件的指针一律
   删除或更新。
7. **指针有效性**：块内每个相对路径必须在写入时确认存在（死链 = 腐化）；
   任务完成摘除块时同步确认详情文档已进 archive。
8. **矛盾即修**：任何时刻发现摘要块与详情层/archive 矛盾，当场修正，不留到
   下轮。

### 详情层与关联文档的膨胀防线（同一战法，覆盖 handoff 及其关联文档）

摘要块的两种死法同样杀死详情层。多轮更新 handoff 文件及其关联文档时逐条对照
（2026-10-11 pgo-fork 第二刀沉淀：交接卡整段复述四参照取证全文被用户叫停）：

1. **原地覆盖，禁止逐批追加**：进度更新重写同一小节；「上一批/上一阶段/再上
   一批」式历史小节是膨胀开始的标志，历史整体入 archive。
2. **渐进式披露**：每条最多一两句 + 指针；取证、拍板细则、交付清单、测试结果、
   文案、坑的唯一权威 = 专题文档（规格分册 / 取证附录 / pitfalls 式专题），
   卡内整段复述 = 腐化，当场砍。
3. **冷信息及时归档**：已完成小节、已验证 checklist、失效开口项随每次更新移出
   热层——整卡完成 → 整文件入 archive；局部完成 → 该节删剪（史实需要留存的
   移入 archive 对应卡），冷信息不滞留热层。
4. **滞留上下文清理**：每轮更新后通读一遍，逐句自问「这句还成立吗？」——过时
   阶段描述、已勾未删的验证项、指向已归档/已删除文件的死链一律清除。
5. **关联文档各归其位**：坑类长期知识进 pitfalls 式专题文档；**活件清单
   （验收 checklist 等）≤ 5 行才留在热层，超出即下沉专题文档、交接只留
   一行指针**——「活件」不等于「豁免瘦身」（2026-10-11 pgo-fork 第三刀：
   60 行验收清单留热层被叫停，迁入规格 §14）；热文件明显超预算（如 >50 行）
   时先问「哪些该冷了」，而不是继续往里写。
6. **两块核心 + 摘要**（2026-10-11 用户定稿）：交接文件的核心 = ①上一批
   **完成记录**——可核查（commit、测试证据路径、权威规格各一行，接手者能
   审计「上批真落地了吗」）②**交接任务单**——下一批要实现的任务（做什么 /
   计划在哪 / 怎么验收 / 约束）；其余部分全部摘要 + 指针。配套**文档地图**
   留在卡内或入口层（哪类信息在哪个专题文件），保证脱离会话记忆也能凭指针
   定位详情——定位链靠仓库自身的文件，靠记忆就违背了自足。

## 写入流程（保存进度）

1. **读取 `AGENTS.md`**：确认是否已有该任务的摘要块。
2. **确认 `.handoff/` 目录存在**：不存在则创建。
3. **写入完整 handoff 文档**：按上方模板填充，覆盖旧文件，内容必须是当前最新状态。
4. **覆盖重写 `AGENTS.md` 摘要块**：定位该任务已有的块，**整块替换**（没有才插入）；对照「膨胀与腐化防线」逐条自检——禁止新增 `###` 兄弟小节，禁止把本轮细节抄进块里。
5. **写入后自检（必做）**：
   - `AGENTS.md` 中每个活跃任务恰好一个摘要块，无已完成任务的残留块；
   - 每个活跃块 ≤ 10 行、无"上一批/上一阶段"式历史叙事，且块内每个指针指向真实存在的文件（无死链）；
   - 热层 handoff 文件同样无历史叙事小节、无整段复述外部文档内容；已完成小节
     /已验证项已移出或勾销（冷信息归档），指针无死链；
   - `.handoff/` 根下不应存在 `status: completed` 的文档（应已在 `archive/`）。
   自检不过就先修复再收口——归档移动漏做或摘要块膨胀腐化，都会随会话数累积上下文负担。
6. **告知用户**：确认文件已写入，并告知 handoff 位置。

## 完成清理（自动摘除）

当 Agent 确认任务已全部完成并通过验收标准时：

1. **从 `AGENTS.md` 中删除该任务的摘要块**。
2. **将 handoff 文档整体移入 `.handoff/archive/`**（文件名不变；归档只追加、不改写，不做摘要化删减），移动前把 `status` 字段改为 `completed`。
3. **告知用户**：`"✅ 任务 <任务名> 已完成，AGENTS.md 中的摘要引用块已清除，文档已归档至 .handoff/archive/。"`
