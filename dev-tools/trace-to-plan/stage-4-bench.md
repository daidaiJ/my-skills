# Stage 4 — bench 闭环

> 由 SKILL.md 阶段路由加载。本轮目标：验证修复成效，确认问题关闭。

## 流程

1. **修前 baseline**：量化记录当前指标（延迟 / 吞吐 / 资源占用，同一场景）——若 stage-3 已记录则直接引用
2. **实施**：交给 `sdd-implement` 按 plan.md 逐项实现
3. **修后对比**：同一 bench 场景、同一数据量，对比基线
4. **回归**：功能不受影响（复用 `code-review` 双轴验证）
5. **收尾**：更新 `issue.md` 状态至 `verified` / `closed`，index.md 时间线补齐验证结果（bench 数据）

## 硬性标准

- **未做修后对比的问题不算完成**——性能工作没有"凭感觉好了"
- 对比不达标：回 stage-2 重新评估（根因是否完整？方案是否偏航？），不允许悄悄接受
- 修复引入功能回退：回 stage-3 调整方案，不绕过回归
