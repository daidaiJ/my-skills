# Stage 3 — 方案规划与可重放修复包

> 由 SKILL.md 阶段路由加载。本轮目标：为已决策问题产出可执行的实施计划。

## 每个入选问题产出

- **解决思路**：方案 + 预期效果（量化目标，如"P99 从 2s 降到 500ms"）+ **业务价值陈述**（解决后业务得到什么）
- **风险与副作用**：兼容性、行为变化、回滚难度
- **验证方式**：怎么证明修好了（同一 bench 场景对比）

## 依赖分析与排序

- **共享热点的问题先做**——修一处多处受益，且避免重复触达同一模块
- 标注修复间依赖：A 修完 B 才能测（如先拆慢查询才能并行化）
- 独立问题可并行
- 综合排序遵守 stage-2 的**优先级排序宗旨**：低风险低复杂度快见效在前，高风险高复杂度延后或拆分——依赖约束只决定"谁必须先做"，宗旨决定"谁先动手"

## 产出：可重放 plan.md

写入 `.issue/plan.md`。每个修复步骤必须**自包含**：

- 改哪里（文件 / 函数 / 模块）
- 改成什么（改动方式，含关键代码意图）
- 验证命令（如何证明修复生效）
- 依赖顺序（哪些步骤必须先完成）
- 基线数据（修前 bench 数值，供对比）

不引用本会话说过但未落盘的任何话——plan.md 是给"没参加过调查的 agent"读的。

**重放校验标准**：一个新 agent 只读 `.issue/` 内文件（不读本会话记录），能否独立完成修复并跑通验证？不能，则 plan.md 写得不完整。

## 交接准备

方案定稿后更新 index.md 状态至 `implementing`，时间线补齐"修复"段（引用 plan.md）。
