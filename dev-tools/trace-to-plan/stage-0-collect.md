# Stage 0 — 多边信号收集

> 由 SKILL.md 阶段路由加载。本轮目标：收集信号、沉淀线索。

## 输入通道（每轮）

用户可按任意组合提供：

1. **约定目录**：日志 / metrics 导出文件放入 `.issue/`（如 `.issue/logs/`），自动扫描
2. **临时指定路径**：`trace-to-plan 日志在 /tmp/app.log，先看下昨晚的报错`
3. **直接粘贴**：错误信息、trace 片段、指标数值、慢请求样例
4. **现象口述**：什么时候慢、多慢、影响谁、是否偶发

每类输入都整理为一条线索（`clues/NNN-*.md`），附来源、时间窗口、原始内容。

## 四类信号

**单源是线索，多源交叉才升级为候选**：

| 信号源 | 采集要点 |
|--------|---------|
| **现象描述** | 用户/issue 怎么说：什么时候、多慢（数字）、影响谁、是否偶发；区分主观感受与客观指标（"感觉卡" vs "P99 从 200ms 到 2s"） |
| **trace 日志** | 慢调用链（span 耗时、跨服务链路）、错误/超时/重试风暴、反模式日志（N+1、循环内 I/O）、问题时段日志聚集 |
| **metrics 指标** | 延迟（P50/P95/P99 趋势）、吞吐、错误率、CPU/内存/GC/连接池/队列积压；问题时段 vs 正常时段、发布前后对比、峰值形态（尖峰/阶梯/周期） |
| **项目代码** | 热点路径、复杂度（O(n²)、全表扫描、锁竞争）、缓存缺失、无界增长、跨服务调用深度 |
